# 🤝 Руководство по участию в разработке

Спасибо за интерес к **True Cost of War** — открытому проекту Peaceful World MTÜ. Мы приветствуем исправления, переводы, проверку источников, улучшения доступности и технические предложения.

## Основной принцип разработки

Ветка `main` защищена. Не отправляйте рабочие изменения напрямую в `main`: создайте отдельную ветку и **Pull Request**. Перед объединением GitHub автоматически запускает обязательный check `qa`.

Локально ту же базовую проверку можно запустить командой:

```bash
python scripts/qa.py
```

Для JavaScript-проверок скрипту также нужен установленный Node.js.

## 🌍 Локализация

Сейчас проект находится в переходной архитектуре: каждая языковая папка содержит собственные `calculator.html` и `embed.html`. В дальнейшем тексты будут вынесены в общий localization layer, поэтому не размножайте дополнительную логику без необходимости.

### Как исправить существующий перевод

1. Перейдите в папку нужного языка, например `/ru` или `/fr`.
2. Исправьте соответствующий текст в `calculator.html` и, если тот же текст используется в share/embed-интерфейсе, в `embed.html`.
3. Не меняйте числовые параметры модели в локализованном HTML как часть переводческого PR.
4. Создайте Pull Request и кратко опишите изменение.
5. Убедитесь, что обязательный `qa` завершился успешно.

### Как предложить новый язык

Пока миграция локализации не завершена, сначала откройте **Issue** или **Discussion**. Мы согласуем код языка, направление письма, формат чисел и объём перевода. Это позволит не создавать ещё одну большую HTML-копию непосредственно перед переходом на общую архитектуру локалей.

## 📊 Данные и методология

Числа в калькуляторе — не обычный контент. Изменение значения может изменить все headline-результаты сразу на нескольких языках.

`data/model.json` фиксирует канонический **legacy baseline** текущей модели. Он нужен для контроля технической целостности и не означает, что все исторические значения методологически одобрены.

Рабочий аудит источников и направления для v2 находятся в:

`data/METHODOLOGY_AUDIT_v0.1.md`

Если вы предлагаете новые данные:

1. Откройте **Issue** или **Discussion**.
2. Укажите первичный или максимально авторитетный источник, год, географический охват, единицы и временной горизонт.
3. Объясните, является ли показатель наблюдаемыми данными, модельным предположением или opportunity-cost benchmark.
4. Не подменяйте исторический ряд умножением одного современного годового значения на количество лет.
5. После согласования изменение должно пройти regression/QA checks через Pull Request.

Предпочтительные источники — первичные базы и публикации исследовательских/международных организаций (например SIPRI, UCDP, структуры ООН и профильные международные агентства), а не пересказы в СМИ.

## 🧪 Что сейчас проверяет QA

Автоматическая проверка контролирует наличие всех поддерживаемых языковых вариантов, базовую целостность HTML, синтаксис встроенного JavaScript, структуру числовой модели, числовые guardrails и соответствие локальных копий каноническому baseline в `data/model.json` с явно документированными legacy-исключениями.

QA не доказывает истинность методологии. Он защищает проект от случайных технических регрессий; научная и методологическая проверка остаётся отдельным этапом.

## 📝 Задачи и предложения

Для ошибок и конкретных предложений используйте **Issues**. Для более широкого обсуждения методологии, архитектуры или будущих направлений можно использовать **Discussions**.

Старайтесь делать Pull Request небольшим и тематическим: одна проблема или один класс изменений за раз. Так изменение проще проверить и, при необходимости, откатить.
